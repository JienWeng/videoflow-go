# Remaining-risk test round — 2026-11-14

Follow-up to the 190-check E2E round at revision `b3f398c`. This round specifically targets the previously listed gaps rather than claiming another complete application certification. Provider endpoints and native engines were mocked; storage and databases for integration mutations were temporary. Production project records and credentials were not changed.

## Confirmed issue and fix

**RISK-01 — Scenes/Videos selection semantics, high accessibility severity.** Axe classified `aria-required-children` as critical at desktop and mobile widths: both master panes declared `role="listbox"`, while their children were regular selection buttons, loading/empty messages and recovery actions. Empty Scenes also contains the New story button. This gives assistive technology an invalid widget structure.

Changed the two containers to named button groups and exposed selected rows with `aria-pressed` in `SceneListItem.svelte` and the render rows. Supplemental arrow-key selection is retained. A narrow Svelte compiler exception documents keyboard support on the focusable group; no axe rule or design-detector rule was disabled. Verification checks empty and populated panes, ArrowDown selection, announced pressed state and automated WCAG rules. Raw RED evidence is `/tmp/videoflow-risk-e2e/a11y-red/report.json`.

**RISK-04 — invisible group keyboard focus, high accessibility severity.** The collaborative browser confirmed the focused Scenes container had computed `outline-style: none`; the added regression assertion failed with the same result (`focus-red/report.json`). Added an inset, theme-colored outline for keyboard focus to both master panes. Final selection checks assert the outline is visible as well as checking ArrowDown and pressed state.

**RISK-02 — populated scene text contrast, high accessibility severity.** The populated-state follow-up found serious `color-contrast` failures hidden by empty fixtures: Next hints at 3.75–4.42:1, the unsaved badge at 3.5:1, the scene ID at 2.18:1 and future workflow labels at 2.76:1. Removed opacity from those text tokens and gave the amber badge explicit light/dark text colors. Layout, typography and the product palette remain intact. Evidence before this fix: `scale-a11y-green/report.json` (despite the provisional directory name, this run correctly exited 1 on its remaining contrast findings).

**RISK-03 — shared light-theme contrast, high accessibility severity.** Light-theme verification found muted foreground at 4.43:1 on sidebar surfaces and 4.13:1 on muted tags; failed badges measured 4:1. Darkened the light-theme muted and destructive tokens while preserving their hues and leaving dark-theme tokens unchanged. Also corrected the detailed Unsaved badge (3.19:1 on white) with the same light/dark amber colors as the master row. RED evidence: `release-light/report.json`. These are verified existing issues, not claims that this session introduced regressions.

## Test tooling and reproduction

New scripts: `scripts/e2e_project_transfer.mjs`, `scripts/e2e_scale_accessibility.mjs`, `scripts/e2e_webkit.mjs`. Their defaults and header comments identify fixture requirements. Transfer checks `/e2e/counters` before any mutation. The documented repository Playwright fixture workflow was used; the collaborative browser separately confirmed the shipped Scenes group and no horizontal overflow.

External test tools were installed under `/tmp/videoflow-risk-tools`, without changing application dependencies: Playwright 1.65.1, @axe-core/playwright 4.14.0, HyperFrames 0.9.33. WebKit's Linux dependencies were installed on the test host. Original/captioned video fixtures came from the prior isolated media/editor round. For scale/a11y, configure `PLAYWRIGHT_MODULE`, `AXE_MODULE`, `CHROME_BIN`, `E2E_BASE_URL` and `E2E_OUTPUT` as needed. `E2E_A11Y_ONLY=1` skips stress setup; `E2E_A11Y_ROUTES=/scenes,/render` limits route scans while retaining populated-selection/dialog checks.

Uncached backend command: `go test -count=1 -json -p 2 ./internal/api ./internal/jobs ./internal/director ./internal/composition` in the FFmpeg/Python-equipped test image. The initial run passed 122 tests and skipped the opt-in fixture and two real runtime tests. Both real runtime tests were then explicitly enabled on the host and passed; the browser fixture separately passed on shutdown. A first renderer attempt in the minimal Go image failed because Chrome's shared libraries were absent; the same pinned runtime passed on the provisioned host. A WebKit media attempt with the injected video offscreen timed out; making the player visible passed play/seek at both widths. These environment/test corrections are not product regressions.

The initial scale scan's two page errors came from the test returning an invalid preflight shape (`[]` instead of an object with `missing`); the final fixture provides the API's actual shape. Initial axe violations were retained as RED evidence rather than suppressed.

One early light scan sampled Add assets during its loading/opacity transition and reported 3.27:1. The settled-page rerun reproduced neither that violation nor any page error at either width. The harness now waits for intercepted network traffic to settle before auditing; `assets-light-settled/report.json` retains that focused verification. No product styling was changed to hide the transient result.

Raw reports/logs are under `/tmp/videoflow-risk-e2e/`. The companion results JSON retains individual checks, backend test names/outcomes, accessibility violations and incomplete checks. The isolated backend and Vite server were stopped after transfer/WebKit completion. The running production frontend was rebuilt with the semantic fix. No requested work was deferred for approval.
