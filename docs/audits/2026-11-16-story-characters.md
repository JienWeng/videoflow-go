# Guided story characters — November 16

The reported failure occurred before script planning: the project had no characters, but the selected native session retained an unavailable character ID. Guided creator inherited that saved selection even when its own cast was empty. A new guided request now binds its own explicit cast, including an empty cast, while retaining the native thread and leaving saved session references unchanged. Explicit invalid/foreign cast IDs still fail ownership checks.

Guided creator now offers **Create missing characters from the story**, on by default and visible even for empty projects. The explicit Create video request authorizes bounded character profiles as part of story planning. It does not generate extra portraits, configure voices or render video automatically. Existing selected profiles remain authoritative; unselected existing names require an explicit selection rather than silent adoption or duplication.

The planner returns additional profiles with temporary `new:key` references. The application validates keys, sizes, cast limits, names, scene casts and dialogue speakers, then assigns real IDs. Profiles, script and scenes save in one transaction. Foreign/unknown bindings, opt-out violations and invalid drafts leave no partial records. Selected profiles are not overwritten; reused descriptors are normalized in the stored script to their approved identity. Explicit empty scene casts remain empty, with a nil-only compatibility fallback for older drafts that omit cast fields.

Each saved scene receives its own actual character notes/reference bindings, including newly planned profiles. Shot and keyframe requests use that scene-local context. This prevents another scene's actors/references from leaking into the request. Guided Render explicitly requests scene-cast scope, so the stale saved session reference cannot reappear after keyframe approval. Normal render requests keep their existing selection behavior; ownership, keyframe approval, frozen-identity and saved-voice gates remain in place.

Created profile IDs and saved story/scene IDs remain in operation results if a later image stage fails. The UI exposes character review, refreshes its list after completion/failure and points spoken-dialogue users to Voices & captions. A restored failure is labelled Last attempt failed. No failed operation is automatically retried, no saved native selection is silently cleared, and the user's real video request was not resubmitted during implementation.
