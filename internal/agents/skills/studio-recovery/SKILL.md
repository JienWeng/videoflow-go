# Recover a Studio workflow

Use this when someone asks what went wrong, what is ready, why a result looks wrong, or how to continue interrupted work.

Start with `production_progress` in the context. It lists each scene's stage, a plain-language explanation and one next step, and it is the same status the user sees in Studio. Use its wording so chat and the screen agree. When `next.action` matches an action card (generate_shots, generate_assets, storyboard, render_scene, retry_render), offer that card; never offer retry_render for a scene marked blocked. Each scene's `video` says where its video stands. A scene `waiting_on_service` has an earlier request the video service never answered: offer check_video (free) with its `job_id`, or stop_waiting when the user would rather move on and accepts the service might still bill it. Several scenes without video go in one render_scenes. Then check the selected project and scene. Match the user's symptom to a saved operation, render job, linked asset or current scene setup. A recent failure on another scene is only a lead. An empty activity list may be incomplete. When the evidence is missing, say what you need and point to the specific Activity entry or scene control. Never ask for a password, device code or API key in chat.

Tell the user what happened, what work they still have, and the next useful action. Name buttons by their visible label (for example **Refresh storyboard**) and never call them “cards”; after a page reload earlier buttons are gone, so say where to find the action (the suggestion under the chat, or the scene's “What to do next” box in Story view). Use their scene and character names. Offer one compatible action card when available. Use a destination in the app when the repair requires a setting or manual edit. Mention potential provider use before generation. After a run, use the returned result and saved state to explain what changed. An accepted request or an operation marked succeeded can still contain a visual verdict of needs_attention.

| Where the flow stopped | Evidence to check | Smallest useful recovery |
| --- | --- | --- |
| Project, selection or chat history | Active project, selected item and session, interrupted turn, proposal revision | Restore the intended session. For a missing or foreign character, refresh the project selection and prepare a fresh proposal. Preserve the conversation and existing assets. |
| Backend connection or stalled progress | Activity status, saved output, the scene's `video` state and job_id | A lost connection leaves the outcome unknown. Offer check_video before anything that might spend credits again; offer stop_waiting only when the user accepts the earlier request might be billed. |
| Local planning or provider setup | Selected engine, CLI detection, account sign-in, provider route, model capabilities | Guide local sign-in through AI sessions or provider setup through Settings. CLI detection alone cannot verify login. Claude plans with a configured image API. Codex can use native images, with fallback on established unsupported input or unavailability. An ambiguous native attempt needs checking before another try. |
| Story brief or shot plan | Confirmed style, delivery, language, scene count, duration, saved shots and model limits | Ask only for missing decisions. Preserve custom entries. For incomplete shots or invalid timing, repair that scene's plan and verify shot durations against the scene before any render. |
| Cast, props or location | Scene connections, existing identities, missing or excluded references | Reuse the linked item when appropriate. Generate the missing character sheet or scene asset through the corresponding card. Confirm the resulting asset ID is bound to the intended scene or character. |
| Style drift, framing or stale storyboard | Project look, scene look, character reference medium, shot prompts, linked storyboard revision and requested aspect | Offer audit_storyboard on the intended scene. Inspection checks the pixels; optional repair makes one candidate and checks it. Report its verdict. If it still fails, address the conflicting reference or direction before generating again. Verify actual dimensions separately when framing matters. Treat historical accuracy as unverified without supporting sources. |
| Video, voices or unexpected cost | Has shots, current storyboard, native or silent audio, render grouping, displayed calls and seconds | Use the scene render card. Reuse matching clips. Let the user see the paid-call plan before starting video. A shot count alone does not establish the charge. |
| Assembly, music, captions or export | Completed source clips, final audio, cue timing, saved edit revision and export result | Continue from existing clips in the composition editor. Use actual audio for captions, verify timing and play the exported result before reporting audiovisual success. |
| Unknown or repeated failure | Last successful stage, exact failing stage, affected scene, whether an external request was submitted | Preserve completed work. Give the Activity entry and one concrete check. If the cause remains unknown, say so. An uncertain payment or repeated identical failure ends automatic attempts. |

Example reply when the evidence supports it: “The opening scene still has its two shots. Its storyboard predates your documentary look. Choose **Run visual audit** to compare the image with the scene. Enable **Repair if needed** if you want one replacement.”
